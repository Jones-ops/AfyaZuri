# Data protection controls

This page maps Afyazuri's controls to the **Kenya Data Protection Act, 2019** (DPA), the Data Protection (General) Regulations 2021, the ODPC's guidance for the health sector, and the **Digital Health Act, 2023** (DHA). It describes what the software does. It is not legal advice. Each facility, as data controller, still needs its own registration with the ODPC, a data protection impact assessment, policies and staff training.

**Status key:** ✅ implemented and tested · 🟡 partly in place (schema or groundwork) · ⏳ planned for the phase shown

## Keys and secrets

| Secret            | Protects                          | If lost                                                        | If leaked                                                           |
| ----------------- | --------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------- |
| `ENCRYPTION_KEY`  | Encrypted columns                 | Encrypted fields are unrecoverable                             | Rotate (Phase 10 adds re-encryption); treat as a breach             |
| `BLIND_INDEX_KEY` | Searchability of encrypted fields | Exact search on those fields stops working until it is rebuilt | Values could be guessed by dictionary attack; rotate                |
| `BACKUP_KEY`      | Backup files                      | Backups are unrecoverable                                      | Anyone with the files can read them; rotate and take a fresh backup |
| `JWT_SECRET`      | Session tokens                    | Everyone must sign in again                                    | Tokens could be forged; rotate immediately                          |
| `PG_PASSWORD`     | Database superuser                | Reset with local server access                                 | Database is localhost-only, but rotate                              |

`npm run secrets` generates these values into `.env` with mode 600. Store an offline copy of the first three keys (for example sealed and printed, or in a password manager held by two named officers), **separately from the backups**.

## Operator checklist (per facility)

- [ ] Register with the ODPC as a data controller (and any processors).
- [ ] Complete a DPIA before go-live; review it yearly.
- [ ] Use HTTPS on the LAN (`TLS_CERT_FILE`/`TLS_KEY_FILE`) or keep the server on an isolated clinical VLAN.
- [ ] Set `REQUIRE_2FA_PRIVILEGED=true` once admins and finance staff have enrolled.
- [ ] Enable nightly backups with an off-site copy; test a restore every quarter ([backup-restore.md](backup-restore.md)).
- [ ] Review the audit log and the break-glass list weekly.
- [ ] Disable accounts the day staff leave; review role assignments quarterly.
